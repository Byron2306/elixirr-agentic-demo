# Claim Boundaries

This file is part of the demo, not legal padding. It distinguishes live behavior, source-system evidence and portability fixtures.

## Global

- A successful demo run proves the demonstrated path, not universal system correctness.
- Imported artifacts retain their original repository/ref/path provenance.
- Replays are labelled `replay`; they are never presented as live execution.
- Historical acceptance receipts are evidence of the tested build and conditions, not permanent guarantees.
- AI-assisted development is disclosed when relevant; generated code is not treated as verification.

## Vesper / DIO

May demonstrate live conversation, context, routing and governed product/commercial behavior where the current runtime supports them.

Do not infer market validation, legal clearance, autonomous release authority or enterprise-scale production volume from a successful run.

## BEAST

May demonstrate bounded coding-agent planning, tool use, SourcePlan/patch execution, verification and evidence where the selected current branch supports them.

Provider benchmark results are dated route-fitness evidence, not permanent provider rankings.

## Seraph

MCP/tool access is not itself authorization. The demo should preserve policy/token checks and VNS independent observation.

ATT&CK mappings are not automatically equivalent to validated defense. Preserve the source evidence maturity distinction.

## ARDA / Valinor

Read-only inspection may demonstrate the current machine's kernel, BPF authority, measured identity and attestation/verifier state.

Do not imply every historical ARDA cryptographic path was native post-quantum cryptography. Do not claim remote/off-box verification unless the live machine actually uses it at demo time.
